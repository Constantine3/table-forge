# Agent Note: Event-sourced LLM game engine

Status: implemented

English | [中文](2026-08-14-event-sourced-llm-game-engine.zh.md)

## Problem

The harness had reusable Agent, Session, Remote, browser, and persistence infrastructure, but no game authority. Implementing each social game directly as an Agent prompt would mix probabilistic decisions with rule enforcement, expose hidden actions through shared context, and make recovery depend on model transcripts.

## Decision

Games use a deterministic definition behind an event-sourced match engine. Definitions publish deployment-resolved setup schemas, validate JSON inputs, emit rule events, reduce state, declare action windows, and project views without I/O. An open window declares whether participating seat ids, submission status, and controller failures are public or limited to required seats. Each actionable seat supplies its own current JSON schema, which permits role-dependent actions without revealing another seat's choices. The engine owns command serialization, lossless-JSON exact-input idempotency independent of object key order, atomic header-and-initial-event creation, append-before-publish ordering, reconstruction, controller dispatch, durable abandonment, and restart recovery when compatible definitions and controllers register. Registration subscriptions replay currently available entries, and recovery runs after the activation stack, so persisted work does not depend on plugin activation order. Recovery contains each record failure and validates persisted controller configurations before dispatch; unavailable definitions and current-format open matches with incompatible controllers remain available for audit without blocking compatible matches. Match format `1` persists window audience metadata and original command inputs, and direct reads reject pre-release format `0`. Product listings exclude unsupported formats and game rules versions, and Remote restore treats a persisted selection for either as unavailable, while SQLite leaves the row untouched. SQLite is the durable provider, requires exactly one supported schema row, and closes a connection whose schema validation fails.

AI participation is a controller provider rather than rule behavior. Every AI seat receives an independent Agent and Session scoped to one game-action tool and a complete deployment-configured game prompt; generic coding-agent and workspace context is excluded. The shipped prompt requires Simplified Chinese for every reasoning block, natural-language answer, and public statement while preserving protocol identifiers exactly. The controller applies the configured per-request output-token limit to newly created and resumed seat Agents, so provider selection does not change the game action budget. The selected adapter translates that provider-neutral limit to its wire protocol. A timed-out seat uses the reasoning effort mapped to its exact provider and model for the provider retry and later controller attempts until an action succeeds; route validation requires that effort to exist. The controller registers the exact tool for one request, binds it to the current action window, and removes it after the Agent becomes idle instead of asking the model to reproduce an opaque routing id. A successful game action concludes its Agent turn, eliminating the otherwise mandatory acknowledgement request after the tool result. The model-visible Session request event includes the window id, projected observation, and seat-specific action schema. A seat sees only its projected observation, and controller work is serialized per seat from one idle state to the next. Abandonment cancels and drains all seat work before completion, and provider teardown drains every owned controller task before its services disappear. Simultaneous submissions remain sealed in match projections until the complete action window resolves. Remote creation resolves the requested provider/model and checks deployment-configured route availability from the game Host before persistence. This permits a LAN-only provider and a cloud fallback to coexist without browser-side network assumptions. Browser submissions are assigned only to the match's human seat, and browser retry clears every current block without accepting private seat ids.

The `game` profile composes these roles over existing base and Web bundles. The generic browser root stores only the selected match id, reconstructs the table from the durable Remote view after reload, lists durable matches, and dispatches installed catalog and board contributions by game id. Restore, open, refresh, active play, and abandonment do not read AI Sessions. A user can explicitly load local Session audits only after normal completion; abandoned matches never reveal undisclosed identities or offer audit loading. The audit reader paginates every AI seat's complete history, maps each game-sourced model turn back to its action schema, pairs game-tool calls with their outcomes, and sorts reasoning, natural-language output, and action arguments into one event-time timeline. Before storing the browser projection, it replaces all model text and action fields from decisions declared anonymous by the game with explicit redaction markers. Each rendered row identifies the seat, action stage, model turn, clock time, and content kind; a failed history read names the unavailable seat. Exhausted controller attempts append a blocked-seat event; restart preserves the block without automatic redispatch, and an operator can explicitly retry current blocks or abandon the match. The profile gives its maximum-reasoning local model a ten-minute stream idle allowance because reasoning may produce no transport chunks for longer than the generic interactive timeout.

`game-rps` proves human-versus-AI, AI-versus-AI, configurable rounds, all nine outcomes, and hidden simultaneous actions. `game-avalon` proves role-dependent schemas and private projections with one human and four independently configured AI seats. Match setup can pin the human to any role in the fixed deck or use the private seed for every assignment; the resulting Merlin, Assassin, two Loyal Servants, and Minion mapping is persisted for deterministic replay. The leader proposes an initial team and clockwise or counterclockwise discussion; the adjacent seat starts, the non-leaders speak sequentially so later speakers receive earlier statements, and the leader's final summary action includes the final team. That team may retain or replace initial members and becomes the only team exposed to the sealed statement-free vote. Resolution counts approvals and rejections without copying the seat-to-choice mapping into the rule event, so every public and seat projection receives the same anonymous aggregate. An approved team resets the consecutive-rejection count before its sealed quest actions; only five uninterrupted rejections trigger that evil victory. Quest history reveals only failure counts. After three successful missions, evil players receive sequential private statement windows in clockwise order after the Assassin, the Assassin speaks last, and only then receives the target action. Active non-evil projections receive neither evil speaker identities nor statements; normal resolution reveals the roles and discussion. Neither game adds behavior to `agent-loop`.

## Alternatives considered

- **Encode game rules in prompts**: rejected because model output cannot be the authority for legality, scoring, replay, or hidden information.
- **Give a match one shared Agent**: rejected because shared history leaks private observations and prevents independent provider, model, and persona configuration.
- **Store only final state**: rejected because idempotent recovery, audit, replay, and future spectator projections need committed facts rather than overwritten snapshots.
- **Build a game-specific server outside Cordis**: rejected because definitions, controllers, persistence, transport, and UI are replaceable plugin roles and already match the repository's composition model.
- **Give every game one static action schema**: rejected because Avalon legality changes by phase and role; a union would advertise forbidden quest failure or private assassination fields to the wrong seat.
- **Expose every window and rely on the browser to hide private metadata**: rejected because public Remote views, durable table lists, and non-participating seats must not receive private action ownership in the first place.
- **Keep one RPS-specific browser root and add Avalon branches to it**: rejected because game-specific setup, state parsing, and presentation would accumulate in shared product state instead of following the definition plugin boundary.
- **Attach each public statement to its team vote**: rejected because statements would appear only after the simultaneous vote resolves, so players could not react to one another before choosing a vote.
- **Lock the initial team before discussion**: rejected because the ordered statements must be able to inform the leader's final team choice; direction remains fixed because it already determined who spoke in what order.
- **Persist named team votes and hide them only in the browser**: rejected because replayed projections and later model observations would retain information that the game rules declare anonymous.
- **Apply the human's role choice only in the browser**: rejected because the deterministic rule definition must validate the choice and persist the resulting complete assignment.
- **Move directly from the third successful mission to target selection**: rejected because separate private statement windows make each evil player's contribution durable, visible to later evil speakers, and attributable in the post-finish AI audit.
- **Use request timeouts without a token budget**: rejected because a timeout aborts an unfinished action but does not limit the completion work attempted before that deadline; token and idle limits cover different failure modes.
- **Retry a timeout at the original reasoning effort**: rejected because it repeats the latency conditions that exhausted the first allowance without adding information that warrants the same reasoning budget.
- **Delete unsupported match rows during startup**: rejected because a format rejection does not authorize silent destruction; incompatible rows remain stored and excluded from product restore and listing.

## Consequences

New games implement a pure definition and a keyed browser contribution while reusing lifecycle, persistence, AI control, Remote transport, and product composition. Match and model transcripts have explicit separate ownership, and post-finish audit remains a user action rather than an automatic side effect of loading a match. The merged audit timeline makes cross-seat chronology and accepted non-anonymous actions legible after disclosure, at the cost of reading every model-history page when the user requests it. Browser storage chooses a table but never becomes match authority; clearing it leaves server history intact. A stored selection with an unsupported match format or game rules version returns the browser to the catalog without deleting its database row. The shipped 16,384-token request limit bounds completion work across both game providers but does not promise a wall-clock duration; maximum reasoning may still keep a table waiting for several minutes. A timeout lowers later local-model requests from `max` to `high` reasoning and cloud-model requests from `high` to `low` until the action succeeds; a successful tool call ends the turn without another model request. Exhausting the attempts still blocks the affected seat rather than inventing a move. Avalon gains observable discussion and ordered reactions at the cost of five sequential statement actions and four AI model turns per team proposal in its fixed one-human composition. The leader's fifth action carries both prose and the final team, which makes the discussion consequential but gives that action a distinct schema. Anonymous vote history supports deduction from the aggregate while deliberately removing named-voter evidence from replay, future model context, and post-finish audit. Its endgame adds two sequential evil statements; one or both require AI turns according to the human's chosen role. Pinning the human role makes a selected perspective reproducible but reduces assignment uncertainty for that player. A game can evolve its rules through a versioned definition, but a running match never silently switches versions. Private window support costs a match-format rejection for pre-release format `0`; the product intentionally chooses the new privacy foundation instead of a compatibility shim.
