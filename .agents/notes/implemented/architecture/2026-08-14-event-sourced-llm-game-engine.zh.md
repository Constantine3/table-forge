# Agent Note: 事件溯源的 LLM 游戏引擎

Status: implemented

[English](2026-08-14-event-sourced-llm-game-engine.md) | 中文

## 问题

Harness 已有可复用的 Agent、Session、Remote、浏览器和持久化基础设施，但没有游戏权威。若把每个社交游戏直接实现为 Agent 提示词，就会混合概率性决策与规则执行，通过共享上下文泄露隐藏动作，并使恢复依赖模型对话记录。

## 决策

游戏使用事件溯源对局引擎背后的确定性定义。定义发布经部署配置解析后的设置 schema，负责验证 JSON 输入、产生规则事件、归约状态、声明动作窗口并无 I/O 地投影视图。引擎拥有命令串行化、完全输入一致的幂等性、头记录与初始事件的原子创建、先追加再发布的顺序、重建、控制器分派、持久化放弃，以及兼容定义和控制器注册时的重启恢复。注册订阅会回放当前已有条目，恢复则在激活调用栈结束后运行，因此持久化工作不依赖插件激活顺序。恢复会隔离每条记录的失败，并在分派前校验已持久化的控制器配置；不可用定义和不兼容的未结束对局继续保留供审计，但不会阻断兼容对局。SQLite 是持久化提供方，要求恰好一条受支持的 schema 记录，并在 schema 校验失败时关闭连接。

AI 参与是控制器提供方，而不是规则行为。每个 AI 席位获得一个独立 Agent 与 Session，其范围内只有一个游戏动作工具和一份部署配置的完整游戏提示；通用编码 agent 与工作区上下文会被排除。控制器将该工具绑定到当前动作窗口，而不要求模型复述不透明的路由 id。席位只能看到自己的投影观察，且控制器工作按席位从一次空闲状态串行到下一次空闲状态。放弃对局会取消并排空所有席位工作，提供方销毁也会在服务消失前排空其拥有的控制器任务。同时动作在完整动作窗口解决前始终封存在对局投影之外。Remote 创建会在持久化前解析所请求的提供方与模型，并从游戏 Host 检查部署配置的路由可达性。因此局域网提供方与云端备选可以共存，而无需让浏览器猜测网络环境。浏览器提交则只能归属于对局的人类席位。

`game` profile 在既有 base 与 Web bundle 上装配这些角色。浏览器只存储选中的对局 id，并在重新加载后根据持久化 Remote 视图重建牌桌；它还会列出持久化对局，并把每个 AI 席位的 Session 读取为本地审计视图。控制器尝试耗尽后会追加阻塞席位事件；重启会保留该阻塞而不自动重新分派，操作员可以明确重试席位或结束对局。profile 为最高推理档的本地模型提供十分钟流空闲容限，因为推理可能在超过通用交互超时的时间内不产生传输数据块。初始 `game-rps` 插件验证人类对 AI、AI 对 AI、可配置局数、全部九种结果和隐藏的同时动作，而不向 `agent-loop` 添加行为。

## 曾考虑的替代方案

- **在提示词中编码游戏规则**：否决，因为模型输出不能成为合法性、计分、回放或隐藏信息的权威。
- **一场对局共享一个 Agent**：否决，因为共享历史会泄露私有观察，也无法独立配置提供方、模型与角色设定。
- **只存储最终状态**：否决，因为幂等恢复、审计、回放和未来的观战投影需要已提交事实，而非被覆盖的快照。
- **在 Cordis 外构建游戏专用服务器**：否决，因为规则定义、控制器、持久化、传输与 UI 都是可替换插件角色，与仓库现有装配模型一致。

## 结果

新游戏实现一个纯定义，即可复用生命周期、持久化、AI 控制、Remote 传输和产品装配。对局日志与模型对话记录的所有权得到明确区分。浏览器存储选择牌桌，但绝不成为对局权威；清除该记录不会删除服务端历史。最高推理可能让牌桌等待数分钟，而耗尽流空闲容限后会阻塞受影响席位，不会伪造动作。游戏可通过带版本的定义演进规则，但运行中的对局不会静默切换版本。首个浏览器产品刻意专用于剪刀石头布；更丰富的观战工作流仍应作为同一组服务的扩展，而不是修改 Agent loop 的理由。
