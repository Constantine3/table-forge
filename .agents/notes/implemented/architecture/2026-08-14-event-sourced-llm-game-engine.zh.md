# Agent Note: 事件溯源的 LLM 游戏引擎

Status: implemented

[English](2026-08-14-event-sourced-llm-game-engine.md) | 中文

## 问题

Harness 已有可复用的 Agent、Session、Remote、浏览器和持久化基础设施，但没有游戏权威。若把每个社交游戏直接实现为 Agent 提示词，就会混合概率性决策与规则执行，通过共享上下文泄露隐藏动作，并使恢复依赖模型对话记录。

## 决策

游戏使用事件溯源对局引擎背后的确定性定义。定义发布经部署配置解析后的设置 schema，负责验证 JSON 输入、产生规则事件、归约状态、声明动作窗口并无 I/O 地投影视图。开放窗口声明参与席位 id、提交状态与控制器故障是公开，还是仅限必需行动的席位。每个可行动席位提供自己的当前 JSON schema，从而支持按角色变化的动作，而不泄露其他席位的选择。引擎拥有命令串行化、不受对象键顺序影响的无损 JSON 完全输入幂等性、头记录与初始事件的原子创建、先追加再发布的顺序、重建、控制器分派、持久化放弃，以及兼容定义和控制器注册时的重启恢复。注册订阅会回放当前已有条目，恢复则在激活调用栈结束后运行，因此持久化工作不依赖插件激活顺序。恢复会隔离每条记录的失败，并在分派前校验已持久化的控制器配置；不可用定义和控制器不兼容的当前格式未结束对局继续保留供审计，但不会阻断兼容对局。对局格式 `1` 持久化窗口受众元数据和原始命令输入，直接读取会拒绝预发布格式 `0`。产品列表排除不受支持的格式与游戏规则版本，Remote 恢复把指向任一此类记录的持久选择视为不可用，而 SQLite 不会改动该行。SQLite 是持久化提供方，要求恰好一条受支持的 schema 记录，并在 schema 校验失败时关闭连接。

AI 参与是控制器提供方，而不是规则行为。每个 AI 席位获得一个独立 Agent 与 Session，其范围内只有一个游戏动作工具和一份部署配置的完整游戏提示；通用编码 agent 与工作区上下文会被排除。交付提示要求每段思维链、自然语言回答与公开发言使用简体中文，同时保持协议标识符的精确值。控制器会把已配置的单次请求输出 token 限制应用到新建和恢复的席位 Agent，因此切换提供方不会改变游戏动作预算；选定的适配器会把这个提供方无关的限制转换为对应的线协议字段。发生超时的席位会在提供方重试和后续控制器尝试中使用映射到其精确提供方与模型的推理档，直至动作成功；路由校验要求模型提供该档位。控制器为一次请求注册确切工具、将它绑定到当前动作窗口，并在 Agent 进入空闲后移除，而不要求模型复述不透明的路由 id。游戏动作成功后会结束对应的 Agent 回合，省去工具结果之后原本必须发起的确认请求。模型可见的 Session 请求事件包含窗口 id、投影观察和席位专属动作 schema。席位只能看到自己的投影观察，且控制器工作按席位从一次空闲状态串行到下一次空闲状态。放弃对局会取消并排空所有席位工作，提供方销毁也会在服务消失前排空其拥有的控制器任务。同时动作在完整动作窗口解决前始终封存在对局投影之外。Remote 创建会在持久化前解析所请求的提供方与模型，并从游戏 Host 检查部署配置的路由可达性。因此局域网提供方与云端备选可以共存，而无需让浏览器猜测网络环境。浏览器提交只能归属于对局的人类席位；浏览器重试会清除当前全部阻塞，而不接受私有席位 id。

`game` profile 在既有 base 与 Web bundle 上装配这些角色。通用浏览器根界面只存储选中的对局 id，在重新加载后根据持久化 Remote 视图重建牌桌、列出持久化对局，并按游戏 id 分派已安装的目录和棋盘贡献。恢复、打开、刷新、活跃游玩和放弃都不读取 AI Session。用户只能在正常完成后显式载入本地 Session 审计；已放弃对局绝不公开未披露身份，也不提供审计载入。审计读取器会遍历每个 AI 席位的全部历史页，把游戏来源的模型回合映射回动作 schema，将游戏工具调用与结果配对，再把推理、自然语言输出和动作参数按事件时间合并为一条时间线。写入浏览器投影前，它会把游戏声明为匿名的决策所对应的全部模型文本和动作字段替换成显式脱敏标记。每个呈现条目都会标明席位、动作阶段、模型回合、时钟时间和内容类型；历史读取失败时会列出无法读取的席位。选择开启的浏览器通知会把隐藏或失焦页面视为无人关注，并让每个人类可操作窗口最多发出一次通知。前台出现的窗口在完成前仍保留通知资格，只有实际发送通知才会把该窗口记为已经通知。控制器尝试耗尽后会追加阻塞席位事件；重启会保留该阻塞而不自动重新分派，操作员可以明确重试当前阻塞或结束对局。profile 为最高推理档的本地模型提供十分钟流空闲容限，因为推理可能在超过通用交互超时的时间内不产生传输数据块。

`game-rps` 验证人类对 AI、AI 对 AI、可配置局数、全部九种结果和隐藏的同时动作。`game-avalon` 通过一名人类与其余 AI 组成的圆桌或全 AI 圆桌，验证按角色变化的 schema 与私有投影。对局设置会选择五人、六人或七人局，可以把唯一的人类固定为对应牌组中的任一身份，也可以让私有种子分配所有身份；最终的梅林、刺客、两名或三名亚瑟的忠臣与一名或两名莫德雷德的爪牙会持久化，以实现确定回放。存在人类席位时，浏览器会收到该席位的投影；否则只观察不带动作控件的公开投影。棋盘保留圆桌作为主要游玩区域，把五轮任务结果排列在旁边，并通过投影的席位顺序与当前队长样式表达顺时针队长轮换，不会重复显示全部席位。所选规则拥有五轮任务人数、逐轮失败门槛和严格多数的队伍投票门槛。队长提议初选队伍并选择顺时针或逆时针讨论；指定方向上的相邻席位先发言，非队长席位依次发言，让后发言者收到此前陈述，队长最后的归票发言动作包含最终队伍。最终队伍可以保留或更换初选成员，并且是唯一进入不附带陈述的封存投票的队伍。结算会统计赞成票与否决票，但不会把席位到选择的映射复制进规则事件，因此公开投影和各席位投影只会收到相同的匿名汇总；浏览器会在每条收起的历史摘要中显示这些票数。队伍通过后，连续否决计数会在封存任务动作前清零；只有连续五次否决才触发对应的邪方胜利。任务历史只公开失败票数；七人局第四次任务需要两张失败票，其他受支持任务只需一张。席位私有提示会区分公开主张与已记录证据，禁止把汇总票型归因给具名玩家，并补充阵营与阶段策略，但合法性与计分仍归规则定义所有。邪方任务策略要求隐藏身份服从胜利条件，并提供一条顺时针约定，让在队邪方只提交达到门槛所需的匿名失败动作。三次任务成功后，邪方玩家从刺客之后的席位开始沿顺时针依次收到私有发言窗口，刺客最后发言，此后才收到目标动作。活跃的非邪方投影和公开投影都不会收到邪方发言者身份或发言；正常裁定会公开身份与讨论。两种游戏都不向 `agent-loop` 添加行为。

## 曾考虑的替代方案

- **在提示词中编码游戏规则**：否决，因为模型输出不能成为合法性、计分、回放或隐藏信息的权威。
- **一场对局共享一个 Agent**：否决，因为共享历史会泄露私有观察，也无法独立配置提供方、模型与角色设定。
- **只存储最终状态**：否决，因为幂等恢复、审计、回放和未来的观战投影需要已提交事实，而非被覆盖的快照。
- **在 Cordis 外构建游戏专用服务器**：否决，因为规则定义、控制器、持久化、传输与 UI 都是可替换插件角色，与仓库现有装配模型一致。
- **让每个游戏使用一个静态动作 schema**：否决，因为阿瓦隆的合法动作随阶段与身份变化；联合 schema 会向错误席位展示被禁止的任务失败或私有刺杀字段。
- **公开所有窗口，再依赖浏览器隐藏私有元数据**：否决，因为公开 Remote 视图、持久牌桌列表和非参与席位从一开始就不应收到私有动作归属。
- **保留剪刀石头布专用浏览器根界面，再加入阿瓦隆分支**：否决，因为游戏专属设置、状态解析与呈现会堆积在共享产品状态中，而不是遵循规则定义的插件分界。
- **把每句公开发言附在队伍投票上**：否决，因为发言只会在同时投票全部裁定后出现，玩家无法在选择投票前回应其他人的观点。
- **讨论开始后锁定初选队伍**：否决，因为有序发言必须能够影响队长的最终组队；发言方向保持不变，因为它已经决定了发言顺序。
- **持久化具名队伍投票并只在浏览器隐藏**：否决，因为回放投影和后续模型观察仍会保留游戏规则声明为匿名的信息。
- **只在浏览器应用人类的身份选择**：否决，因为确定性规则定义必须验证该选择，并持久化最终的完整身份分配。
- **把全 AI 阿瓦隆注册为另一个游戏定义**：否决，因为控制器组成已经能够区分人类参与和公开观察，无需改变阿瓦隆事件、阶段或规则。
- **把新增的每种阿瓦隆人数分别注册为独立游戏定义**：否决，因为受支持的圆桌人数共享事件语义、阶段、身份和呈现；经过验证的设置选项可以让同一个规则所有者管理不同的牌组、任务人数、失败门槛和投票门槛。
- **人类窗口首次在前台渲染时就记为已经通知**：否决，因为玩家可以让该动作保持待处理并切走页面，从而在通知唯一有用的时刻将其抑制。
- **三次任务成功后直接进入目标选择**：否决，因为独立的私有发言窗口可以持久化每名邪方玩家的贡献，让后续邪方发言者看到，并在赛后 AI 审计中明确归属。
- **只使用请求超时而不设置 token 预算**：否决，因为超时会中止未完成的动作，却不会限制截止前尝试的生成工作；token 限制与空闲限制覆盖不同故障模式。
- **超时后以原推理档重试**：否决，因为这会重复耗尽第一次容限的延迟条件，又没有新增信息值得使用相同的推理预算。
- **在启动时删除不受支持的对局记录**：否决，因为格式拒绝不授权静默破坏数据；不兼容记录会保留在存储中，并从产品恢复与列表中排除。

## 结果

新游戏实现一个纯定义和一个 keyed 浏览器贡献，即可复用生命周期、持久化、AI 控制、Remote 传输和产品装配。对局日志与模型对话记录的所有权得到明确区分，赛后审计是用户操作，而不是载入对局的自动副作用。合并的审计时间线会在披露后明确呈现跨席位时序与已接受的非匿名动作，代价是用户请求审计时需要读取全部模型历史页。浏览器存储选择牌桌，但绝不成为对局权威；清除该记录不会删除服务端历史。对局格式或游戏规则版本不受支持的已存选择会让浏览器返回游戏目录，而不会删除对应数据库行。交付的单次请求 16,384 token 限制会约束两个游戏提供方上的生成工作，但不承诺请求耗时；最高推理仍可能让牌桌等待数分钟。一次超时会把后续本地模型请求从 `max` 降到 `high` 推理档，并把云端模型请求从 `high` 降到 `low`，直至动作成功；工具调用成功后则直接结束回合，不再发起模型请求。尝试耗尽时仍会阻塞受影响席位，而不会伪造动作。阿瓦隆以每次组队增加五个、六个或七个串行发言动作为代价，获得可观察讨论和按顺序回应。一名人类参与的圆桌每次提案需要四个、五个或六个 AI 模型回合，全 AI 圆桌则需要五个、六个或七个。队长的最后一个动作同时携带文本与最终队伍，这让讨论能够影响组队，但也使该动作使用不同的 schema。匿名投票历史允许玩家根据汇总票型推断，同时有意从回放、后续模型上下文和赛后审计中移除具名投票证据。五人和六人终局会增加两个串行邪方发言动作，七人终局会增加三个；全 AI 圆桌的全部动作都会触发 AI 回合，人类为邪方时混合圆桌少触发一个。固定人类身份可以稳定复现选定视角，但会减少该玩家面对的身份分配不确定性。全 AI 圆桌允许浏览器观察自主游玩，但在正常裁定前不会暴露私有身份投影。游戏可通过带版本的定义演进规则，但运行中的对局不会静默切换版本。私有窗口支持使预发布格式 `0` 被拒绝；产品选择新的隐私基础，而不加入兼容垫片。
