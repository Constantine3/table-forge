# `@deepseek-ai/dsh-game-controller-agent`

[English](README.md) | 中文

该提供方注册 `agent` 席位控制器。每个 AI 席位拥有独立 Agent 与 Session，只接收定义投影出的自身观察；游戏组合不挂载全局工具时，它只能调用为该次控制器请求注册的确切 `submit_game_action` 实例。它的席位范围完整系统提示会屏蔽通用编码 agent 段和运行时工作区上下文。持久化的游戏请求 Session 事件记录到达模型的窗口 id、观察和席位专属动作 schema。

工具由控制器绑定到精确的当前窗口 id，因此模型只提交动作，不会输错路由数据。延迟调用无法为后续回合选择动作，幂等键也会将模型的工具调用 id 限定到该窗口和席位。提交成功会结束 Agent 回合，因此不会再发起第二次模型请求来生成多余的确认语。每次尝试先确认请求已持久写入收件箱，再等待整个 Agent 进入空闲；该区间结束后仍没有被接受的动作时，提供方最多按 `maxAttemptsPerAction`（默认 2）重试，随后拒绝驱动且不会编造动作。重启后，它会恢复已物化的席位 Session，而不是替换其审计历史。

提供方和模型来自持久席位规范。显示名称来自席位，`playerInstruction` 则是所有 AI 玩家共享的部署配置。`maxTokensPerRequest`（默认 16,384）会限制新建或恢复的 AI 席位发起的每次模型请求；选定的适配器会把这个提供方无关的限制转换成对应的线协议字段。它限制生成 token 数量，而不是请求耗时。`timeoutRetryReasoningEfforts` 将精确的提供方和模型 id 映射到一次 `TIMEOUT` 后使用的推理档位，直至该席位提交游戏动作；模型校验会拒绝不提供映射档位的已配置路由。对局事件保持权威；回放绝不会调用模型。

部署可为“模型目录能够解析、但网络端点可能不可达”的路由配置 `providerProbes`。控制器从实际发起模型请求的游戏 Host 探测这些端点。不可达的局域网路由会在设置页禁用，而可达的云端路由仍可选择；创建对局还会在持久化前重复检查。

所有尝试失败后，引擎会记录席位故障并公开阻塞对局。操作员可以在浏览器中重试该席位而不丢失对局，也可以结束对局。

## 模型体验

### AI 席位回合

#### 模型看到什么

模型收到配置的玩家指令、游戏规则、席位范围观察、当前窗口 id 和唯一工具 `submit_game_action`。随附游戏 profile 要求每段思维链、自然语言回答与公开发言使用简体中文，并要求模型每次提交前显式推理当前观察、历史回合、比分与目标、不确定性与隐藏信息、对手倾向、候选动作、风险和可能的反制，同时不得编造席位不可观察的信息。协议 JSON 键、动作标签、枚举值与席位 id 仍保持精确值。模型不会收到原始对局事件、运行时工作区上下文或其他席位的 Session。

#### Token 影响

每个动作请求一次 Agent 回合。首个步骤成功调用工具后不会再请求模型生成确认语。每次模型请求使用已配置的 `maxTokensPerRequest` 限制；空闲回合未有效提交时最多重试 `maxAttemptsPerAction - 1` 次，发生 `TIMEOUT` 后的请求会使用精确路由对应的 `timeoutRetryReasoningEfforts` 配置项。

#### KV Cache 影响

每个席位有独立缓存血缘。角色设定与规则是稳定候选；观察与窗口 id 在回合间变化。

## 已知限制与后续工作

- 提供方探针只检查 TCP 可达性；身份验证和 API 兼容性仍由首次模型请求验证。
