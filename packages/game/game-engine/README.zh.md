# `@deepseek-ai/dsh-game-engine`

[English](README.md) | 中文

`dsh-game-engine` 按对局串行化命令，以单次原子操作创建头记录和初始事件，在发布修订号前追加完整事件批次，并从持久日志重建所有视图。同时提交在游戏定义产生裁定事件前保持私有。规则定义可对非参与者隐藏动作窗口的参与席位、提交状态与控制器故障；只有可以行动的人类投影会收到当前 JSON schema。定义或控制器新注册后，引擎会先验证持久化席位路由，再恢复兼容的未完成 AI 动作窗口；单个不可用定义或不兼容控制器不会阻断其他对局恢复。产品列表会忽略不受支持的预发布对局格式与游戏规则版本，Remote 恢复会将二者视为不可用；直接服务读取仍会拒绝这些记录。

Remote 接口在创建前验证已配置的 AI 提供方、模型以及 Host 侧路由可达性。浏览器动作只会归属于对局中唯一的人类席位；纯 AI 对局不接受浏览器动作。控制器失败会成为持久化的阻塞席位事件，因此重启不会再次分派同一个失败窗口。浏览器重试操作不接受也不暴露私有席位 id，而是清除当前全部阻塞；内部服务仍为受信消费者保留定向重试。放弃对局会写入持久终态事件，并在完成前排空控制器工作。

`MemoryGamePersistence` 支持测试和一次性组合。持久产品需在加载 `GameEngine` 前提供 `ctx.gamePersistence`。

## 模型体验

### 控制器分派

#### 模型看到什么

引擎调用 `modelPrompt`，只向控制器传递该席位观察、动作 schema 与当前窗口 id。它自身不发送模型请求。

#### Token 影响

零直接 token；请求成本由所选控制器拥有。

#### KV Cache 影响

无直接影响。事件重建不会改写 AI Session。

## 已知限制与后续工作

- 初始产品组合中，一场对局最多支持一个人类席位。
